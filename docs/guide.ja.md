# B-Side ガイド

[← README に戻る](../README.ja.md)

<a id="features"></a>

## できること

- **ライブラリ**：ファイルのタグから作るアーティスト、アルバム、曲、ジャンル。タグがないときはフォルダー名とファイル名で補います（`Artist\Album\01 Title.flac`）。アルバムはアーティスト、タイトル、年で並べ替えられ、曲の一覧は 1 万曲でもなめらかにスクロールします。
- **アーティストとアルバムのページ**：アルバムのジャケットやアーティスト画像の色に染まります。アルバムページにはファイルから読んだフォーマット（コーデック、サンプルレート、ビット深度）、ディスクと長さが表示され、歌詞のある曲やクラウドにしかない曲に印が付きます。
- **再生**：アルバムはそのページから、アーティストのアルバムはアーティストページから再生できます。曲を押すと、その曲からアルバムの最後まで再生します。曲やアルバムのメニュー（**⋯**）には **次に再生**、
  **キューに追加**、**アルバムへ移動**、**アーティストへ移動** があります。AIMP が閉じていれば、再生すると起動します。
- **検索**：アーティスト、アルバム、曲をすぐに検索。大文字小文字やアクセントは区別せず（`rios` で
  *Ríos de Ámbar y Sal* が見つかります）、日本語や中国語の名前の中の語も見つけます。パネルのどこからでも `/` または
  `Ctrl+K` で検索に移れます。
- **再生中**：ジャケット、曲名、アーティスト、アルバム（それぞれライブラリのページを開きます）、1 行のフォーマット（`FLAC | 16 ビット | 44.1 kHz | 738 kbps | ステレオ`）、そしてすべての操作：再生/一時停止、前へ、次へ、シーク（バーをドラッグするか ←/→）、音量、ミュート、シャッフル、リピート。`Space` で再生と一時停止を切り替えます。
- **歌詞**：ファイルのタグ（FLAC `LYRICS`/`UNSYNCEDLYRICS`、MP3 `USLT`/`SYLT`）または曲の隣の `.lrc` から。歌詞のある曲では再生中の画面に表示されます。同期歌詞は現在の行をハイライトしながら曲に合わせて進み、行を押すとその位置へ移動します。曲名の横の丸い **歌詞** ボタンで、どのスキンでも表示と非表示を切り替えられます。歌詞がない曲では、その理由を伝えます。隅の A− と A+ で大きさを 4 段階に変えられ、B-Side はそれを覚えています。
- **サイドバーのために**：幅が狭いときはスマートフォンのアプリのように、再生中、ライブラリ、検索のタブとミニプレーヤーで動きます。サイドバーを広げると、ライブラリや検索が左に、再生中が右に並びます。
- **ジャケットの色**（CD スキン）：ニュートラルな黒をベースに、再生中のジャケットのパレットがタブバーからミニプレーヤーまですべての面を染め、ライトでもダークでも文字は読みやすいまま（WCAG AA）。アルバムページはそのアルバム自身のジャケットの色になります。
- **わかりやすい状態表示**：フォルダーの選択、スキャン中、AIMP が閉じている（*AIMP を開く* ボタン付き）、
  AIMP が応答しない、オフライン。
- **あなたの言語で**：隅の国旗から English、Español、Deutsch、日本語、中文、Русский を選べます。最初は Orca の言語で始まり、選んだ言語を覚えます。ライト／ダークのテーマは Orca に合わせます。

<a id="skins"></a>

### スキン

左上のロゴを押してスキンを選びます。B-Side は選択を覚えます。どのスキンもパネル全体（再生中、ライブラリ、検索、歌詞、ミニプレーヤー、フォーマット行）を Orca のライト／ダークテーマで作り変え、文字は WCAG AA のコントラストを保ちます。

- **CD**（デフォルト）：ニュートラルな黒に Manrope。再生中のジャケットの色がすべての面を染め、ほぼモノクロのジャケットはほぼ黒のまま控えめなアクセントになります。
- **レコード**：真空管アンプのような、レザーとウォルナットと古金のリスニングルーム。Cormorant と EB Garamond、スモールキャップ、選択中のタブを細い金で示す暗いタブバー、シャンパンゴールドのリングが付いた暗いノブ。
- **カセット**：ピクセルで描いた 80 年代のカセットデッキ。VT323 と Press Start 2P、ウォークマンのキーのようなシアンの縁取りを付けた濃い紫、小さなアクセントとしてのフューシャ、LED の進行メーター。

ロゴは AIMP と一緒に動きます。CD は固定の光沢の下で虹色に回り、レコードは 33⅓ で回ってトーンアームが下り、一時停止で上がります。カセットのリールが回ります。アニメーションは音楽が鳴っていてパネルが見えているときだけ動き、Windows の「アニメーション効果」がオフなら止まります（その場合もロゴは光、ランプ、レコード上のトーンアームで再生中を示します）。


<a id="requirements"></a>

## 必要なもの

- Windows 10 または 11
- [Git](https://git-scm.com/download/win)（`install.ps1` を使う手順 2 のときだけ）
- [Orca](https://github.com/stablyai/orca) 1.4.248 以降
- Microsoft Store 版 AIMP（インストーラーがユーザー単位で、管理者権限なしで入れます）

<a id="install"></a>

## インストール

Orca 内のターミナルで実行します（`orca` コマンドが使えます）。AIMP がすでにあれば手順 1 だけで十分です。AIMP がない場合や新しい PC では、手順 2 だけで両方が済みます。

**1. プラグインをインストールする**

```powershell
orca plugin install icaceresc/b-side
```

B-Side はあなたの PC でコードを実行します。ライブラリを読み、AIMP とやり取りするために Orca が起動する小さなワーカー（*trusted worker*）です。そのため初回は Orca がいったん止まり、プラグインに与えられるもの（専用のストレージと専用の設定だけ）を示して、末尾に `--approve <コード>` を付けた同じコマンドを表示します。そのコマンドを実行すると、承認してインストールします。

**2. AIMP を準備する**

```powershell
git clone https://github.com/icaceresc/b-side.git
cd b-side
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

Windows は既定でスクリプトをブロックするため、`-ExecutionPolicy Bypass` はこの 1 回の実行にだけ適用されます。`install.ps1` は AIMP がなければインストールし、Store 版の設定保存の不具合を直し、
My Clouds のストリーミングを有効にします。手順 1 も代わりに行います。GitHub からプラグインをインストールまたは更新し、Orca が承認を求めたらその承認コマンドを表示するので、新しい PC ではこのスクリプトだけで済みます。何度実行しても安全です。オプション：

- `-SkipSettings`: AIMP のインストールと設定保存の不具合の修正だけを行い、AIMP の設定には触れません。
- `-SkipPlugin`: AIMP の準備だけを行い、プラグインはインストールしません。

あとは Orca の右サイドバーから **B-Side** を開き、音楽フォルダーを選ぶだけです。

<a id="library-folders"></a>

## 音楽フォルダーを選ぶ

最初に、パネルが音楽の場所をたずねます。この PC で音楽が入ったフォルダーを提案します：Windows のミュージックフォルダーと、各 OneDrive の音楽フォルダー（*Music*、*Música*、*Musik*、*音楽*…）で、それぞれ大きなサブフォルダーと曲数も示します。1 つ以上選ぶか、別のフォルダーのパスを貼り付けて、
**これらのフォルダーを使う** を押します。B-Side が読み込めるフォルダーは 16 個までです。

フォルダーはいつでも変えられます。パネル（ライブラリのオプションの **フォルダーを変更**）か、Orca の
**Settings › Plugins › B-Side › Library folders** で 1 行に 1 つずつ指定します。この設定が空なら、B-Side は
Windows のミュージックフォルダーを使います。

インデックス作成はバックグラウンドで行われ、その間も見て回れます。428 個の FLAC ファイルのコレクションでは最初のスキャンが約 2 秒でした。以後、パネルは保存したインデックスですぐに開き、次のスキャンでは変更されたファイルだけを読み直します。

<a id="update"></a>

## アップデート

```powershell
orca plugin update icaceresc.b-side
```

新しいバージョンがより多くのアクセスを求める場合にだけ、Orca は再び承認を求めます（2.0 は設定のため、2.3.1 は **Native helper** の設定のために求めました）。Orca はその変更を示し、`--approve <コード>` を付けた同じコマンドを表示するので、それを実行してください。承認するまでは、今のバージョンがそのまま動きます。`install.ps1` を使っている場合は、そのクローンで `git pull` を実行すると最新になります。スクリプトを再実行するとプラグインも更新されます。

<a id="aimp-setting"></a>

## B-Side が AIMP で再生するしくみ

AIMP の Remote API は再生を操作できますがファイルを読み込めないため、B-Side はエクスプローラーと同じ方法で曲を AIMP に渡します。アルバムや曲を再生すると、B-Side は AIMP に最初の曲を開くよう頼みます。AIMP はプレイリスト **Default** を空にしてその曲を追加し、再生します。続いて B-Side がアルバムの残りを追加します。
**キューに追加** は AIMP が再生中のプレイリストの最後に曲を追加し、**次に再生** は再生中の曲のすぐ後ろに入れます（AIMP が自分のプレイリストを再生しているときは最後に）。何も再生していなければ、どちらも曲を再生します。

これは AIMP の 1 つの設定に依存しており、B-Side がそれを変えることはありません：**環境設定 › プレイリスト ›
ファイルの追加 › 外部アプリケーションからファイルを追加 › デフォルト動作** を AIMP の既定値
**空のプレイリストに追加** のままにしておいてください（英語では *Preferences › Playlist › File adding ›
Open files from external applications › Default action: Add to empty playlist "Default"*）。ほかの値でも AIMP は曲を再生しますが、毎回新しいプレイリストのタブに入ったり（*新規プレイリストを作成*）、開いているプレイリストに追加されたり（*現在のプレイリストに追加*）し、アルバムの残りはそのプレイリストの最後に入ります。

途中の曲から始めるとき、B-Side はアルバムやリスト全体を読み込み、AIMP をミュートしたまま（その間だけシャッフルもオフにして）「次へ」で選んだ曲まで進めます。そのため「前へ」で前の曲にも戻れます。約 2 秒かかり、その後ミュートとシャッフルは元の状態に戻ります。

<a id="two-ways-to-use-it"></a>

## クラウドにある音楽

2026 年 11 月に、FLAC 324 曲（8.1 GB）の OneDrive コレクションでテストしました。音楽の置き方は 3 つあり、B-Side はどれでも使えます。

**この PC：すべて使える。** 音楽をこの PC のフォルダー（または *このデバイス上で常に保持する* にした
OneDrive）に置きます。ディスク上のファイルではすべてが使えます：タグ、ジャケット、歌詞、アーティスト画像。
B-Side が探すものは次の構成でそろいます：

```text
Music\
  Artist\
    artist.jpg            アーティスト画像
    Album\
      cover.jpg           アルバムのジャケット（ファイルのタグにない場合）
      01 Title.flac
      01 Title.lrc        歌詞（ファイルのタグにない場合のみ）
```

**OneDrive のファイル オンデマンド。** OneDrive の音楽フォルダーを B-Side に指定し、*クラウドのみ* にしておきます。B-Side はフォルダー名とファイル名から一覧を作り、クラウドにしかないファイルは開きません（開くとダウンロードされるためです）。テストでは 324 曲が 1 秒かからずにライブラリに入り、何もダウンロードされませんでした。ジャケット、歌詞、アーティスト画像は、この PC に置いてあるファイルの分だけ表示されます。曲を再生すると AIMP がそれを開き、OneDrive が丸ごとダウンロードして、エクスプローラーで **空き領域を増やす** を選ぶまで保持します。パネルは OneDrive にしかない曲やアルバムに印を付けます。

**My Clouds：ストリーミング、同期は不要。** AIMP は内蔵の **My Clouds** で OneDrive（または Google Drive、Dropbox など）から直接再生します。OneDrive アプリは要りません。曲は AIMP で選び、B-Side の再生中タブが表示と操作を行います。職場の PC ではこの方法です：[職場の PC で](#work-pc)を参照してください。

| | この PC | ファイル オンデマンド | My Clouds |
|---|---|---|---|
| B-Side で閲覧・検索 | ✓ | ✓ フォルダー名とファイル名から | AIMP の My Clouds タブで |
| 再生、一時停止、次へ、シーク、音量 | ✓ | ✓ | ✓ |
| ジャケットとその色 | ✓ | この PC にあるジャケット | ✓ AIMP のもの |
| 形式（コーデック、kHz、kbps） | ✓ ビット深度つき | ✓ 再生後 | ✓ ビット深度なし |
| 歌詞とアーティスト画像 | ✓ | この PC にあるファイル | — |
| 鳴り始めるまで | すぐ | OneDrive が曲をダウンロード | 6〜10 秒（実測） |
| ディスク | 自分のファイル | 再生した曲は空き領域を増やすまで残る | AIMP のキャッシュ（終了時に消去） |

<a id="onedrive"></a>

## B-Side で OneDrive に接続する

2.4 の新機能です。B-Side は個人用 OneDrive に自分で読み取り専用でサインインし、選んだフォルダーをライブラリに加えられます。どのアルバムもダウンロードせずに閲覧・検索でき、ジャケット・アーティスト画像・歌詞も表示され、選んだ曲から AIMP で再生できます。

1. **ライブラリ › ⋯ › OneDrive › OneDrive に接続**(初回画面では **または OneDrive に接続**)。
2. B-Side にコードが表示されます。この PC、スマートフォンなどで **microsoft.com/devicelogin** を開き、コードを入力して個人用 Microsoft アカウントでサインインします。B-Side が *ファイルを読み取る* ことと *そのアクセスを維持する* ことの許可を求められたら承諾します。B-Side がパスワードを見ることはありません。
3. B-Side に戻り **フォルダーを選ぶ**: 音楽フォルダーまで開いてチェックし、**このフォルダーを使う** を押します。B-Side が一覧を作り(数百曲なら数秒)、アルバムがクラウドの印付きでライブラリに入ります。変更は 15 分ごと、または **今すぐ同期** で確認します。

**再生。** B-Side は選んだ曲からアルバムの最後までを AIMP に渡すので、その前の曲を AIMP が取得することはなく、「前へ」で選んだ曲より前には戻りません。AIMP の My Clouds に同じ OneDrive があり([My Clouds でストリーミング](#my-clouds))、そこで曲を一度再生していれば、B-Side は My Clouds 自身のアドレスを使います。それまでは約 1 時間有効な OneDrive のダウンロードリンクを使います。どちらでも AIMP がダウンロードするのは再生中の曲だけです。

**B-Side が保存するものと場所。**

- サインイン: リフレッシュトークンを Orca の暗号化されたプラグインシークレットに保存します(Windows があなたのアカウントで保護)。約 1 時間有効なアクセストークンはメモリにだけ置きます。どちらもファイル、ログ、パネルには出ません。
- 選んだフォルダー(名前と ID)は B-Side の Orca ストレージに、そのファイル一覧(名前、サイズ、日付、OneDrive の音楽タグ)は `%LOCALAPPDATA%\B-Side\cloud\index.json` に、ダウンロードしたジャケット・アーティスト画像・歌詞は `%LOCALAPPDATA%\B-Side\cloud\files` に保存します。
- AIMP に渡すプレイリストは `%LOCALAPPDATA%\B-Side\queue` に置き、AIMP が再生した時点(または次回起動時)に削除します。AIMP は自分のプレイリストにアドレスを保存します。ダウンロードリンクは約 1 時間で使えなくなります。

**アクセス許可と取り消し。** *Files.Read*(ファイルの読み取り。B-Side が OneDrive に書き込み・移動・削除をすることはありません)と *offline_access*(1 時間ごとに確認せずアクセスを維持)。OneDrive ページの **接続を解除** でサインアウトし、上記をすべてこの PC から削除します。Microsoft アカウントから B-Side のアクセスも取り消すには **account.live.com/consent/Manage** を開きます。個人用 Microsoft アカウントのみ対応です。

<a id="my-clouds"></a>

## My Clouds からストリーミングする

1. B-Side パネルで **AIMP を開く** を押します。
2. AIMP の **My Clouds** タブを開き、左の列の **All** を右クリックして **ストレージに追加...** を選びます。
3. サービス：**OneDrive**（ほかのサービスも可）› **トークンを取得**。AIMP のサインイン画面は古いブラウザーです。メールアドレスを入力し、**パスワードを使用する** を選び（パスキーやスマートフォンでの承認はここでは使えません）、認証アプリまたは SMS のコードを入力します。アクセスを許可 › **OK**。職場や学校のアカウントがある PC では、先に[職場・学校の PC](#work-account)を読んでください。
4. ツリーで音楽フォルダーをアルバムまで開きます。My Clouds が一覧にするのは選んだフォルダーの曲だけで、サブフォルダーの曲は含みません。曲をダブルクリックします。

インストーラーがストリーミングアクセスを有効にするので、曲はダウンロードしながら再生されます。AIMP は再生した曲をキャッシュ（`%TEMP%\MyCloudsCache`、テストでは 1 曲 23〜46 MB）に保持し、終了時に消去します。Microsoft が *Too Many Requests* と返したら、30 分ほど待ってからもう一度 **トークンを取得** を押してください。

<a id="work-pc"></a>

### 職場の PC で

1. Microsoft Store から AIMP を、そして B-Side（`orca plugin install icaceresc/b-side`）をインストールします。
2. 任意：`install.ps1` を実行します（[インストール](#install)）。My Clouds のストリーミングアクセスが有効になります。
3. 上の手順で、**個人** のアカウントを使って個人用 OneDrive を My Clouds に追加します。
4. AIMP の My Clouds タブから再生し、B-Side で操作・表示します。

会社が AIMP のサインインや個人用 OneDrive をブロックしている場合は、聴きたいアルバムをその PC のフォルダー（または USB ドライブ）にコピーして B-Side に追加してください。そこではすべての機能が使え、歌詞も表示されます。B-Side のヘルパーのダウンロードがブロックされている場合は、**Settings › Plugins › B-Side › Native helper** をオフにします。B-Side は AIMP で再生するため、AIMP が許可されていない環境では再生できません。

<a id="work-account"></a>

> **⚠ 職場・学校の PC：My Clouds には個人のアカウントでサインインしてください。**
>
> Windows に職場や学校のアカウントでサインインしていると、**トークンを取得** が開く Microsoft の
> サインインページがそのアカウントを自動で選ぶことがあり、その場合 My Clouds は職場の OneDrive から
> ストリーミングします。AIMP › **My Clouds** › **ストレージに追加...** › **OneDrive** › **トークンを取得**
> で **別のアカウントを使用する** を選び、個人の Microsoft アカウントでサインインしてください。
> アカウントの種類を聞かれたら **個人用アカウント** を選びます。Windows に職場や学校のアカウントがあると、
> インストーラーが警告します。
>
> - **確認**：My Clouds でそのストレージを開きます。個人の OneDrive のフォルダー（あなたの音楽）が
>   見えれば正しいアカウントです。仕事のファイルや、見覚えのない空の OneDrive が見えたら職場の
>   アカウントです。
> - **修正**：ストレージを右クリック › **ストレージを編集...** › **トークンを取得** で、個人のアカウントで
>   サインインし直します。または右クリック › **ストレージを除去...**（キャッシュも消すには
>   **ローカル キャッシュを削除** にチェック）してから追加し直します。

<a id="sound-quality"></a>

## 音質

B-Side は音声に一切手を加えません。デコードと再生は AIMP が行います。インストーラーは AIMP のエフェクト（フェード、ノーマライザー、アンチクリッピング、ディザー）をオフにします。エンハンサーは AIMP 自身が保持するため、サウンドエフェクトの画面で確認してください。CD 品質のファイルをリサンプリングなしでヘッドホンに届けるには、デバイスの Windows 側フォーマットを同じレートにします：
**設定 › システム › サウンド › 使用するデバイス › 出力設定 › 形式：16 ビット、44100 Hz**。ほかのアプリの音も音楽と一緒に聞こえます。

デバイスを AIMP だけで使いたい場合は、AIMP の **設定 › 再生 › デバイス** で *WASAPI Exclusive* を選びます。
AIMP の再生中、そのデバイスの通知音や通話は聞こえなくなります。

<a id="how-it-works"></a>

## しくみ

```text
Orca パネル ──plugin.request──▶ B-Side ワーカー (Node) ──stdin/stdout──▶ ヘルパー (ネイティブ、Rust) ──▶ AIMP
再生中 · ライブラリ · 検索      インデックス、タグ、                   Remote API：状態、操作、ジャケット
                                検索、キュー                           シェル動詞：開く、プレイリストに追加
                                      │                                フォルダーの一覧、サムネイル
                                      ▼
                         %LOCALAPPDATA%\B-Side\cache
                         library.json · サムネイル · キュー
```

- **ライブラリ**：ヘルパーはディレクトリの情報（名前、サイズ、日時、Windows の属性）だけでフォルダーを一覧にするので、一覧を作るときにファイルは 1 つも開きません。ワーカーはローカルファイルのタグを読み取り専用で読み、アーティスト、アルバム、曲、ジャンルを組み立てて、インデックスを
  `%LOCALAPPDATA%\B-Side\cache\library.json` に保存します。ジャケットとアーティスト画像は、その隣で小さなサムネイルになります。Orca を再起動すると、保存したインデックスですぐに応答し、バックグラウンドで更新します。パネルが受け取るのは名前と不透明な ID だけで、ファイルのパスは渡りません。
- **再生**：ヘルパーは AIMP 自身のファイルの関連付けで、エクスプローラーと同じように曲を開きます（*開く*、アルバムの残りには AIMP の *プレイリストに追加*。`%LOCALAPPDATA%\B-Side\queue` に置く短い `.m3u8` リストを使い、B-Side が 10 分後に削除します）。それ以外（状態、再生/一時停止、シーク、音量、ジャケット）は AIMP 公式の
  Remote API（ウィンドウメッセージと共有メモリ `AIMP2_RemoteInfo`）を通ります。コマンドはすべて許可リストで制限しています。
- **ヘルパー** は小さなネイティブプログラム（`bside-helper-x64.exe`、または `-arm64.exe`、約 0.5 MB）で、
  `native/helper` の Rust コードからビルドしています。何もインストールしなくても動き、使うメモリは数 MB、応答は 1 秒に満たない速さです。リポジトリにはプログラムを含めていません。初めて使うとき、B-Side は自分と同じバージョンの GitHub リリースからこの PC 用のものをダウンロードし、その SHA-256 がそのバージョンのコードに固定された値と一致するときだけ実行します（[ヘルパーを確認する](#verify-helper)）。それまでのあいだ（ダウンロード中、オフライン、ダウンロードや確認の失敗）や、起動できない場合（たとえばウイルス対策ソフトや職場の PC のポリシーにブロックされたときなど）は、B-Side が代わりに PowerShell で書かれた同じヘルパー（`native/aimp-helper.ps1`）を使い、そのことをログ（`orca plugin logs icaceresc.b-side`）に記録します。こちらは C# 部分を一度だけキャッシュフォルダーにコンパイルします。
- Orca はワーカーを *trusted worker* として実行します。この PC 上であなたのユーザーアカウントと同じ権限を持つ Node プロセスなので、Orca は承認を求めます。Orca 自体の権限として求めるのは、専用のストレージ（言語と、パネルを最後に見ていた場所）と専用の設定（音楽フォルダー）だけです。ターミナル、ワークスペース、シークレットは使いません。

<a id="privacy"></a>

## プライバシー

- 選んだフォルダーを読み取り専用で読みます：その一覧と、PC 上にあるファイルのタグ、埋め込みジャケット、歌詞、画像です。クラウドにしかないファイルは開きません。再生中の曲について AIMP が報告する情報（曲名、アーティスト、アルバム、年、フォーマット、ジャケット）も読みます。
- 音楽ファイルを書き換えたり、移動・削除したりすることはありません。書き込むのは `%LOCALAPPDATA%\B-Side`
  （インデックス、サムネイル、キュー、`helper\<バージョン>` にダウンロードしたネイティブヘルパー。PowerShell 版ヘルパーが動いた場合はそのビルドも）と、Orca の専用ストレージと設定だけです。フォルダーのパスはこの PC から出ず、送信されることはありません。
- B-Side で OneDrive に接続しない限り、クラウドのアカウントとそのサインインには触れません。接続した場合は Microsoft 自身のページでサインインし、選んだフォルダーを読み取るだけです([B-Side で OneDrive に接続する](#onedrive))。OneDrive アプリと My Clouds は自分でサインインします。
- ネットワークを使うのは次の 2 つだけです。バージョンごとに一度、ネイティブヘルパー（約 0.5 MB）を HTTPS で
  `https://github.com/icaceresc/b-side/releases/download/v<version>/bside-helper-<x64|arm64>.exe`
  からダウンロードします（GitHub は自社のダウンロード用サーバーから配信します）。送るのはそのリクエストだけです。ダウンロードに失敗したら、後の起動時に、10 分、1 時間、6 時間、1 日と間隔をあけて再試行します。止めるには
  **設定 › Plugins › B-Side › Native helper** をオフにします。B-Side は常に PowerShell 版ヘルパーを使い、ダウンロードしなくなります。また、クラウドからストリーミングした曲の再生中、30 秒ごと（確認に失敗したあとは 5 秒ごと）に `graph.microsoft.com:443` への TCP 接続を開いて閉じ、何も送らずに接続を確認します。
  PC 上のファイルにはそれ以外何も要りません。どのポートでも待ち受けません。
- B-Side で OneDrive に接続したときだけ、Microsoft とも通信します。サインインに `login.microsoftonline.com`、選んだフォルダーの一覧(読み取り専用)に `graph.microsoft.com`、小さなジャケット・アーティスト画像・歌詞(とリンク経由で AIMP が再生する曲)に OneDrive のダウンロードサーバーです。保存するものと取り消し方法: [B-Side で OneDrive に接続する](#onedrive)。

<a id="limitations"></a>

## 制限事項

- Microsoft Store 版 AIMP 4.60 向けに作成・テストしています。AIMP 5 はマシン全体へのインストール（管理者権限）が必要です。
- 再生には、ほかのアプリから開いたファイルに対する AIMP の **デフォルト動作** が既定値のままであることが必要です（[B-Side が AIMP で再生するしくみ](#aimp-setting)）。
- **次に再生** は、AIMP が曲を最後にしか追加できないため、再生中の曲を同じ位置から再開し、短い途切れが入ります。
- B-Side は AIMP のプレイリストを表示しません。再生中のフォーマットは AIMP が報告するもので、ファイルがライブラリにあればビット深度も加わります。アルバムページはファイルから読んだフォーマットを表示します。
- My Clouds からストリーミングした曲はライブラリに入らず（AIMP はクラウドのファイル一覧を外部に提供しません）、歌詞もアーティスト画像も表示されません。
- 音楽フォルダーは 16 個まで。ローカルの Orca ホストのみ対応。
- 職場や学校のアカウントがある PC では、My Clouds がそのアカウントでサインインすることがあります。[職場・学校の PC](#work-account) を参照してください。
- OneDrive への接続は個人用 Microsoft アカウントのみ。クラウドでは「前へ」で選んだ曲より前には戻りません。

<a id="troubleshooting"></a>

## 復旧とアンインストール

- **ライブラリが空、または古い**：フォルダーを確認し（**フォルダーを変更**、または Orca の
  **Settings › Plugins › B-Side › Library folders**）、**再スキャン** を押します。
- **曲を再生するたびに AIMP に新しいプレイリストのタブができる**：AIMP の **デフォルト動作** を
  **空のプレイリストに追加** に戻します（[B-Side が AIMP で再生するしくみ](#aimp-setting)）。
- **AIMP が終了後に設定を忘れる**：リポジトリのクローン（[インストール](#install)の手順 2）で `powershell -ExecutionPolicy Bypass -File .\install.ps1 -SkipSettings -SkipPlugin` を実行します。
- **AIMP が開いているのにパネルが「閉じている」と表示する**：AIMP を再起動すれば、パネルは自動で再接続します。
- **ウイルス対策ソフトが `bside-helper-x64.exe` をブロックする**：B-Side は PowerShell 版ヘルパーで動き続けます（ログに `using the powershell helper` と出ます）。[そのファイルが B-Side のものか確認](#verify-helper)してウイルス対策ソフトで許可すれば、次に Orca を起動したときに B-Side がそれを使います（ウイルス対策ソフトが削除していれば、もう一度ダウンロードします）。ダウンロードしたプログラムを使いたくない PC では、Orca の
  **設定 › Plugins › B-Side** で **Native helper** をオフにしてください。
- **インストーラーによる AIMP の変更を戻す**：元の設定は `AIMP.ini.b-side.bak` として同じ場所に保存されています。
- **アンインストール**：`orca plugin uninstall icaceresc.b-side` を実行します（`-Dev` で読み込んだ場合は
  `orca plugin dev unload <パス>\b-side`）。不要なら Windows の設定 › アプリで AIMP をアンインストールして、クローンを作った場合は削除します。インデックスも消すには `%LOCALAPPDATA%\B-Side` を削除します。

<a id="verify-helper"></a>

## ヘルパーを確認する

ネイティブヘルパーはあなたの PC ではビルドされず、リポジトリにも含まれていません。GitHub Actions がこのリポジトリのコード（`native/helper`、`native/build.mjs` 使用）からビルドし、すべてのテストをそれに対して実行して、
[ビルドの来歴証明](https://docs.github.com/actions/security-for-github-actions/using-artifact-attestations)に署名します。各リリースにはそのビルド `bside-helper-x64.exe` と `bside-helper-arm64.exe` を、SHA-256 を記した `SHA256SUMS` とともに添付しており、同じ SHA-256 がそのバージョンのコード（`src/native-helper.mjs`）に固定されています。初めて使うとき、B-Side は自分と同じバージョンのリリースからこの PC 用のビルドだけをダウンロードして
`%LOCALAPPDATA%\B-Side\helper\<バージョン>` に保存し、SHA-256 が固定値と一致するときだけ実行します。一致しないファイルは実行せずに削除し、理由をログに残します。B-Side の新しいバージョンは自分のビルドをダウンロードし、古いものを削除します。コード署名証明書では署名していないため、Windows には発行元が表示されません。

- **チェックサムを比べる**：リリースの `SHA256SUMS` と照らします：

  ```powershell
  Get-ChildItem "$env:LOCALAPPDATA\B-Side\helper" -Recurse -Filter bside-helper-*.exe | Get-FileHash
  ```

- **どこでビルドされたか確認する**：[GitHub CLI](https://cli.github.com) で、そのファイル、またはリリースのファイルに対して実行します：

  ```powershell
  gh attestation verify "$env:LOCALAPPDATA\B-Side\helper\<バージョン>\bside-helper-x64.exe" --repo icaceresc/b-side
  ```

  ファイルをビルドしたワークフローとコミットが表示されます。クローンでは、`node native/verify.mjs` がダウンロードしたヘルパー（または `--dir <フォルダー>` でリリースのファイル）に同じ確認をし、固定された SHA-256 と、そのコミットのヘルパーコードがお手元のコピーと同じかどうかも確かめます。
- **自分でビルドする**：[Rust](https://rustup.rs) と Visual Studio の C++ ビルドツール（arm64 は ARM64 ツールも）をインストールし、`node native/build.mjs x64` を実行します。rustup がリリースで使っている Rust のバージョン（`native/helper/rust-toolchain.toml`）を取得します。ビルドは決定的です：GitHub のランナーと同じバージョンのコンパイラーとリンカーなら同じバイト列に、違うバージョンなら同じプログラムになります。
  `native/bin`（Git の管理外）にビルドがあるクローンはそれを使い、何もダウンロードしません。
- **ダウンロードしない**：**設定 › Plugins › B-Side** で **Native helper** をオフにします。B-Side は
  PowerShell 版ヘルパーを使います。こちらは `native/aimp-helper.ps1` にあるプレーンテキストです。

<a id="develop"></a>

## 開発

すべてリポジトリのルートから実行します：

```powershell
orca plugin test .        # ユニットテスト (node:test)
orca plugin validate .
orca plugin dev watch . --check --shot .orca/shots
powershell -ExecutionPolicy Bypass -File .\install.ps1 -Dev    # GitHub 版の代わりにこのフォルダーを読み込む
```

AIMP に触れるのはヘルパーだけです。`native/helper`（Rust）を `node native/build.mjs` で `native/bin` にビルドしたもの（Git の管理外。そこにビルドがあればダウンロードの代わりに使います）と、その PowerShell 版 `native/aimp-helper.ps1` です。後者は、ネイティブ版が起動できないときに、ワーカーが `powershell.exe -EncodedCommand` に渡す小さなローダーで起動します。どちらも
stdin/stdout で同じ JSON 行をやり取りし、`test/helper-parity.test.mjs` が同じ応答になることを確認します。
`native/helper` で `cargo test` を実行すると Rust のテストが走り、
`node scripts/measure-helper.mjs --helper native` はメモリ、起動時間、CPU を測ります。ライブラリは `src/library/`、再生は `src/playback.mjs`、パネルは `panel/` にあります。GitHub Actions が
CI ワークフロー（[`.github/workflows/ci.yml`](../.github/workflows/ci.yml)）を Windows で実行します。

Orca のプラグインページ用のアイコン、カバー、スクリーンショットは `python docs/make-assets.py`
（Pillow と Chrome または Edge）で作ります。合成したデモ用ライブラリで実際のパネルを描画するので、パネルを変えたら再実行してください。
